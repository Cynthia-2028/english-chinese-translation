# 英汉互译 / English–Chinese Translation

一个给 AI 助手用的技能包：**既能把英汉互译讲明白，也能直接把活儿干完。**

装上之后，助手在做翻译时不再只是"把意思换成另一种语言"，而是先判断文本类型与语域，再定骨架、填内容、脱离原文改写、最后对照核校。输出的译文符合译入语写作规范，不带翻译腔，也不带 AI 味。

## 它做什么

**讲得清。** 翻译观与标准、英汉十二条硬差异、误译机理分类、可复用的判断规则集、八讲课程结构与评分维度。

**译得准。** 双向覆盖：

| 场景 | 内容 |
|---|---|
| 日常与职场 | 微信消息、对话、邮件、会议纪要、通知、公文、合同条款、宣传材料、商务技术文档 |
| 学术论文 | 中文论文投国际期刊（标题 / 摘要 / 引言 / 综述 / 方法 / 发现 / 讨论），英文文献译成中文供阅读引用 |
| 通用文本 | 长句拆解、名词化还原、隐喻处理、篇章衔接、语域调校 |

**改得动。** 去 AI 味与去译腔各有一份可检索的病灶清单：中文侧的"的的不休、虚化动词、被字滥用"，英文侧的名词化膨胀、空起句、连接词堆叠。附一个自检脚本，扫一遍能把这些可疑处标出来。

## 安装

技能本质是一组 Markdown 加一个脚本，放到助手的技能目录即可。

**WorkBuddy / Claude Code 类环境（用户级）**

```bash
git clone <本仓库地址> ~/.workbuddy/skills/english-chinese-translation
```

Windows：

```powershell
git clone <本仓库地址> $env:USERPROFILE\.workbuddy\skills\english-chinese-translation
```

**项目级**：克隆到项目下的 `.workbuddy/skills/english-chinese-translation`。

放好之后重开一次会话，助手会在遇到翻译任务或翻译问题讲解时自动加载；也可以显式说「用英汉互译技能」。

## 用法

技能本身不需要命令行。跟助手说话就行：

- 「把这段中文译成英文，投期刊用」→ 走学术模块，先定语域，再逐节处理，末尾给术语表
- 「这句英文什么意思，我怀疑我译错了」→ 走陷阱库，先给读法与依据，再给推荐译法
- 「这段话翻译腔太重，帮我改」→ 走去 AI 味模块，给病灶定位与改法
- 「讲讲中译英怎么处理四字格」→ 走讲解四步：判断、依据、对照、规则

自检脚本可以单独跑：

```bash
python scripts/translate_lint.py draft.txt --lang zh      # 扫中文译腔
python scripts/translate_lint.py draft.txt --lang en      # 扫英文 AI 味
python scripts/translate_lint.py draft.txt --lang en --json > report.json
```

输出按 high / mid / low 分级，给行号、片段、改法提示。脚本只报可疑处，不判对错，引文与专名常被误报，需人工复核。

## 设计上的几个取舍

**先定骨架。** 坏译文多数不是词错，是句型搬错。所以每个模块都先问"主干是什么、主语是谁"，再谈选词。

**脱离原文读一遍不可省。** 这是去掉翻译腔的唯一有效动作，因此在主流程里被列为独立的一步，而不是"顺带检查一下"。

**规则要能被执行。** 不写"要自然""要准确"这类无法落地的要求，写成"每句抽象名词超过三个就还原一个为动词""前置定语超过 12 字改小句"这类可数的判据。

**红线单列。** 信息不增删、论断强度不动、术语数字不动、不为通顺改论证方向——这些和"译得漂亮"冲突时，永远后者让步。
